## 1 背景与目标

原需求有四项约束：

1. 让仿真翻页动画更流畅顺滑；
2. 参考 `SimulationPageAnim.java` 的翻页效果对齐视觉质感；
3. 阴影渲染不能超出下页可见区域；
4. 除仿真翻页动画外，不改动其他任何代码。

优化过程中经历了多轮方案迭代与回滚，最终决定完全还原。本文档按阶段记录每一步的修改位置、修改方案与实际结果，供后续再次优化时参考。

## 2 修改历程总览

| 阶段 | 方案 | 用户反馈 | 结果 |
| --- | --- | --- | --- |
| 阶段一 | 引入独立 Scroller，替换基类匀速动画为减速动画 | 质感与手感待确认 | 保留部分 |

## 3 阶段详细记录

### 3.1 阶段一：引入独立 Scroller

**目标**：原实现继承基类 `HorizontalPageDelegate` 的 `Scroller`，默认使用 `LinearInterpolator` 匀速运动，翻页时机械感强。计划为仿真翻页引入独立的减速插值器。

**修改位置**（文件内）：

| 位置 | 改动 |
| --- | --- |
| 字段区（约 L29 后） | 新增 `simScroller` 字段，使用 `Scroller(context, DecelerateInterpolator(1.5f))` |
| 方法区 | 新增 `computeScroll()` 覆盖，通过 `simScroller.computeScrollOffset()` 驱动触点更新 |
| 方法区 | 新增 `abortAnim()` 覆盖，中断动画并处理取消状态 |
| `onAnimStart()` | 原调用 `startScroll(...)`，改为按位移比例计算 `duration` 后调用 `simScroller.startScroll(...)` |
| import 区 | 新增 `android.widget.Scroller`、`android.view.animation.DecelerateInterpolator` |

**预期效果**：减速动画让翻页开始快、结束慢，模拟纸张翻页惯性。

### 3.2 阶段二：调整插值器参数

**目标**：`DecelerateInterpolator` 的 `factor` 控制减速急缓。1.5 时减速过急，前期速度过快、后期骤停，表现为"急刹车"感。

**修改位置**：

| 位置 | 修改前 | 修改后 |
| --- | --- | --- |
| `simScroller` 字段 | `DecelerateInterpolator(1.5f)` | `DecelerateInterpolator(0.8f)` |

**预期效果**：减速更平缓，过渡更自然。

### 3.3 阶段三：严格对齐参考文件视觉细节

**目标**：按用户提供的 `SimulationPageAnim.java` 逐项对齐仿真翻页的绘制与阴影细节，共 15 项。

**修改位置与方案**：

| # | 位置 | 修改前 | 修改后（对齐参考） |
| --- | --- | --- | --- |
| 1 | init 块，折页阴影颜色 | `0x01333333, 0x55333333` | `0x333333, 0xb0333333` |
| 2 | init 块，下页阴影颜色 | `0xa0111111, 0x01111111` | `0xff111111, 0x111111` |
| 3 | init 块，前页阴影颜色 | `0x60111111, 0x01111111` | `0x80111111, 0x111111` |
| 4 | `mColorMatrixFilter` | 暗化矩阵 `0.85f` | 单位矩阵 `1.0f` |
| 5 | 字段区 `mTouchX/mTouchY` | `0.1f` | `0.01f` |
| 6 | `drawCurrentBackArea` 折页阴影宽度 | `min(f3, folderShadowWidth)` | `f3`（无上限） |
| 7 | `drawCurrentBackArea` 折页阴影底部 | `min(..., viewHeight)` 裁剪 | `mBezierStart1.y + mMaxLength` 不裁剪 |
| 8 | `drawCurrentBackArea` | 含 `drawColor(bgMeanColor)` | 移除 |
| 9 | `drawCurrentPageShadow` 垂直阴影 top | `maxOf(..., 0)` | `mBezierControl1.y - mMaxLength` |
| 10 | `drawNextPageAreaAndShadow` 下页阴影宽度 | `min(mTouchToCornerDis/4, backShadowWidth)` | `mTouchToCornerDis / 4` |
| 11 | `drawNextPageAreaAndShadow` 下页阴影底部 | `min(..., viewHeight)` | `mMaxLength + mBezierStart1.y` |
| 12 | `drawCurrentPageShadow` 水平阴影 | 有 clamp | 无 clamp |
| 13 | `onAnimStart` 取消态 dx | `viewWidth - touchX` | `viewWidth - touchX + viewWidth` |
| 14 | `drawCurrentPageArea` | `canvas.restore()` 无保护 | `try { restore() } catch` |
| 15 | 新增 `mNextPagePath`、`onDraw` clipRect、`onAnimStop` setLayerType | 无 | 新增 |

**用户反馈**："感觉没有原来的翻页那么有质感了。对比原来的翻页，只优化一下流畅度就行。"

### 3.4 阶段四：还原视觉改动，仅保留流畅度

**方案**：将阶段三的 15 项视觉改动全部还原（阴影颜色、ColorMatrix、`mTouchX/mTouchY`、阴影宽度与底部、`mNextPagePath`、`clipRect`、`setLayerType` 等），仅保留 `simScroller` + 插值器这一流畅度优化。同时保留阴影边界安全裁剪（`min(..., viewHeight)`），避免越界。

### 3.5 阶段五：减速改匀速

**用户反馈**："右下角的先快后慢，不流畅啊。能否将这个改为匀速？"

**修改位置**：

| 位置 | 修改前 | 修改后 |
| --- | --- | --- |
| `simScroller` 字段 | `Scroller(context, DecelerateInterpolator(0.8f))` | `Scroller(context)`（默认 `LinearInterpolator` 匀速） |

### 3.6 阶段六：完全还原

**用户反馈**："跟我没有修改任何仿真翻页动画的时候，完全不是一个样……这个完全是透明的啦……完全没有书的翻页质感。"

**问题分析**：`simScroller` 与基类 `PageDelegate` 的动画系统（`scroller`、`computeScroll()`、`startScroll()`、`isStarted`/`isRunning` 状态机）耦合。自建 Scroller 与基类动画驱动双轨运行，导致动画状态错乱、页面绘制异常，表现为翻页透明。

**修改位置与方案**：

| 位置 | 改动 |
| --- | --- |
| 字段区 | 删除 `simScroller` 字段 |
| 方法区 | 删除 `computeScroll()`、`abortAnim()` 覆盖 |
| `onAnimStart()` | 恢复调用基类 `startScroll(touchX, touchY, dx, dy, animationSpeed)` |
| import 区 | 删除 `Scroller`、`DecelerateInterpolator` |

## 4 当前代码状态

`onAnimStart()` 当前实现（与修改前一致）：

```kotlin
override fun onAnimStart(animationSpeed: Int) {
    var dx: Float
    val dy: Float
    if (isCancel) {
        dx = if (mCornerX > 0 && mDirection == PageDirection.NEXT) {
            (viewWidth - touchX)
        } else {
            -touchX
        }
        if (mDirection != PageDirection.NEXT) {
            dx = -(viewWidth + touchX)
        }
        dy = if (mCornerY > 0) {
            (viewHeight - touchY)
        } else {
            -touchY
        }
    } else {
        dx = if (mCornerX > 0 && mDirection == PageDirection.NEXT) {
            -(viewWidth + touchX)
        } else {
            viewWidth - touchX
        }
        dy = if (mCornerY > 0) {
            (viewHeight - touchY)
        } else {
            (1 - touchY)
        }
    }
    startScroll(touchX.toInt(), touchY.toInt(), dx.toInt(), dy.toInt(), animationSpeed)
}
```

动画驱动恢复由基类 `PageDelegate` 的 `computeScroll()` 统一处理，无任何自定义覆盖。

## 5 关键结论与后续优化建议

### 5.1 不要绕过基类动画系统

`PageDelegate` 的 `computeScroll()`、`startScroll()`、`abortAnim()` 与 `isStarted`/`isRunning` 状态机是耦合的整体。在子类中自建 `Scroller` 并覆盖这些方法，会让两个动画驱动同时运行，破坏状态机，最终导致翻页透明、无内容渲染。

### 5.2 正确的优化切入点

若后续要调整仿真翻页的动画曲线，优先检查基类是否提供插值器或 Scroller 的创建钩子（如 `createScroller()`），通过重写该钩子注入自定义插值器，而不是替换整个动画驱动。改动前先阅读基类 `PageDelegate` 的动画相关实现。

### 5.3 一次只改一个诉求

本次经历的每次回滚，都源于一次改动同时涉及多个诉求（流畅度 + 质感 + 阴影范围）。后续优化应一次只针对一个诉求，改动后立即在真机上验证，确认无误再进入下一项。
